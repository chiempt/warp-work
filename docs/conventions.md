# Conventions

Mechanical conventions for the Warp repository. Behavioural rules and hard invariants live in
[CLAUDE.md](../CLAUDE.md); domain vocabulary lives in [glossary.md](glossary.md); stack choices and
their reasoning live in [decisions/](decisions/). When this file and CLAUDE.md appear to disagree,
CLAUDE.md wins.

**Status:** written before the first line of code. Revise deliberately, in a commit of its own,
rather than letting the code drift away from it.

---

## 1. Repository layout

Single repository ([ADR 0004](decisions/0004-monorepo-layout.md)), one Go module at the root, one
pnpm project under `apps/web`.

```
warp/
  go.mod                    module github.com/chiempham/warp-work
  Makefile                  every developer command
  sqlc.yaml
  apps/
    api/
      cmd/api/main.go       wiring and graceful shutdown, nothing else
      internal/httpapi/     server, middleware, error envelope, handlers
      Dockerfile
    worker/
      cmd/worker/main.go
      internal/tasks/       task type names and payloads
      Dockerfile
    web/                    Next.js App Router (pnpm)
      src/app/              routes
      src/components/ui/    shadcn primitives — generated, edited deliberately
      src/lib/
  internal/                 shared by api and worker
    domain/                 entities and pure logic — no I/O, no SQL, no HTTP
    store/                  sqlc output — generated, never hand-edited
    config/                 the environment, parsed once into a typed struct
    platform/
      logging/              the JSON logger and its field names
      postgres/             pool and schema-version check
  db/
    embed.go                migrations embedded so a binary knows its schema
    migrations/             goose migrations, immutable once applied
    queries/                hand-written SQL, input to sqlc
    seeds/                  fixtures and the router/extractor test corpora
  docs/
    api/openapi.yaml        the API contract — source of truth for both sides
    decisions/
  infra/
    docker-compose.yml
    .env.example
```

Rules:

- `apps/api` and `apps/worker` both import `internal/`; neither imports the other.
- `internal/domain` imports nothing from `internal/store`, `internal/platform`, or any framework. If
  it needs to, the dependency is pointing the wrong way.
- `cmd/*/main.go` only wires and shuts down. Logic that could be tested does not live there.
- `apps/web` never talks to Postgres. It goes through `apps/api`.
- `db/migrations` is the only place schema is defined. sqlc reads it; it never writes it. There is no
  ORM and no auto-migration in any environment, including local — the services refuse to serve
  against a schema older than the one they were built against, rather than reshaping it themselves.

## 2. Naming

| Thing | Form | Example |
|---|---|---|
| Database table | `snake_case`, plural | `proposed_actions` |
| Database column | `snake_case` | `evidence_signal_id` |
| Foreign key | `<singular_table>_id` | `context_id`, `source_signal_id` |
| Timestamp column | `<verb>_at`, UTC | `ingested_at`, `undone_at` |
| Boolean column | `is_` / `has_` prefix | `is_active`, `is_archived` |
| Enum type | `snake_case` singular, named for the column | `autonomy_level`, `auth_provider` |
| Enum value | lowercase `snake_case` | `needs_reauth` |
| Migration file | `NNNNN_short_description.sql` | `00007_add_autonomy_evidence.sql` |
| Go package | short, lowercase, no underscores, a noun | `router`, `extractor`, `store` |
| Go interface | what it does, `-er` where natural | `SignalIngester`, `Executor` |
| Go test | `TestSubject_condition_expectation` | `TestRouter_noRuleMatches_callsModel` |
| React component | `PascalCase`, one per file | `CommitmentBoard.tsx` |
| TS hook | `useThing` | `useReviewQueue` |
| CSS token | `--color-<domain>-<name>` | `--color-context-study` |
| Env var | `SCREAMING_SNAKE_CASE` | `ANTHROPIC_API_KEY` |
| Directory | `kebab-case` | `docs/decisions/` |

Use the glossary's terms verbatim, in every language. A "message", "item", or "entry" that is really
a `signal` is called a signal — in Go, in SQL, in TSX, and in the interface.

## 3. Database

- Primary keys are UUIDv7 in `uuid` columns, generated by the application (`uuid.NewV7`), not the
  database. Sortable by creation time, no sequence contention, safe to generate before insert.
- Timestamps are `timestamptz`, always stored UTC. Conversion to `Asia/Ho_Chi_Minh` happens in
  `apps/web` only. No query, view, or migration contains a timezone name.
- JSON columns are `jsonb`. Raw external payloads go into `signals.payload` untouched — no
  normalisation, no key filtering, no re-serialisation.
- Every table has `created_at`. Mutable tables also have `updated_at`.
- Enum-like columns are **native Postgres `ENUM` types**, declared together in
  `db/migrations/00002_enums.sql`. Adding a value later is `ALTER TYPE ... ADD VALUE`, which cannot
  run inside a transaction and cannot use the new value in the same one — so it needs its own
  migration marked `-- +goose NO TRANSACTION`. A value can never be removed. Add plausible values up
  front; they are cheap now and awkward later.
- Deletes are soft where history matters (`is_archived`, `status = 'dropped'`). `signals`,
  `executions`, and `audit_log` are never deleted by application code.
- A rule whose violation cannot be undone belongs in the database, not in the application: signals
  are immutable, and the last `auth_identities` row cannot be deleted. Both are triggers, because
  "every code path remembers" is not a guarantee.
- Index every foreign key, and every column in a routing or session-scoped query —
  `signal_contexts (context_id, signal_id)` and `commitments (context_id, status, due_at)` first.
- One `pgvector` index, on `memory_notes.embedding`. A second vector index means the design drifted;
  raise it rather than adding it.

### Migrations

- goose, forward-only in practice. Never edit an applied migration; write a new one.
- Every migration has a `-- +goose Down` that works, or a comment at the top stating why a rollback
  is impossible and what recovery would require.
- Data backfills are separate from schema changes, in their own migration, and idempotent.
- After any migration touching a queried table, regenerate sqlc in the same commit.

### Queries

- SQL lives in `db/queries/*.sql` with sqlc annotations. Generated Go is committed, never edited.
- No dynamic SQL string building. A query with optional filters gets explicit nullable parameters
  (`WHERE ($1::uuid IS NULL OR context_id = $1)`), not concatenation.

## 4. Code style

### Go

- `gofmt` and `go vet` clean, always. Lint with `golangci-lint`; the config is committed.
- `context.Context` is the first parameter of every function doing I/O, and cancellation is honoured.
- Errors wrapped with `%w`, inspected with `errors.Is` / `errors.As`. No sentinel string matching. No
  `panic` outside `main`. Never `_ = err`.
- Accept interfaces, return structs. Interfaces are declared by the consumer, not the producer.
- The router and the extractor are **pure**: they take a signal and return a decision. They do not
  read the clock, the database, or the environment — the clock is a parameter. This is what makes
  re-running extraction over history possible, and it is not negotiable.
- Side effects live at the edges: adapters, store, executor. Everything between is testable with no
  network and no database.
- No package-level mutable state. Dependencies are passed to constructors.
- Comments explain *why*. The schema and the glossary explain *what*.

### TypeScript / React

- Server Components by default. `"use client"` only where interaction genuinely requires it, and as
  far down the tree as possible.
- No `any`. API types come from the generated client in `lib/api/`; do not redeclare them.
- Data fetching in Server Components or route handlers, not in `useEffect`.
- `cn()` for conditional classes. Theme tokens for colour — no ad-hoc hex, no raw palette classes on
  foundational surfaces.
- shadcn components in `components/ui/` are owned source: edit them deliberately, in their own
  commit, and note why. Re-running the CLI must not silently revert an intentional change.

## 5. Errors and logging

- Errors carry a code, not just a message. External failures record the provider, the account, and
  whether a retry is safe.
- A failing connector sets `accounts.status` and `accounts.last_error` and stops. It never falls back
  to a degraded fetch that silently returns partial data.
- `log/slog`, JSON handler, one event per line, always carrying `context_id`, `session_id`, and
  `run_id` where they exist. One logger, injected — no package-level global.
- **Never log at `info` or above:** raw signal payloads, credentials, draft content, or a person's
  contact details. Payload contents are debug-level and redacted by default.
- `run_steps` is the agent debugging trail, not the log file. Every tool call gets a row with its
  input, output, and duration.

## 6. HTTP API

- `docs/api/openapi.yaml` is the contract. `ogen` generates the server under
  `apps/api/internal/api/`; nothing there is hand-written. Echo owns the outer server and the
  operational endpoints; everything under `/api/v1` is the generated handler. See
  [ADR 0007](decisions/0007-openapi-with-ogen.md).
- Routes are declared in the spec, not in Go. An operation with no implementation answers 501.
- Validation belongs in the spec — required parameters, formats, ranges, enums. A handler that
  re-checks what the schema already declares is duplicating the contract.
- REST, plural resource paths, `/api/v1` prefix.
- Every list endpoint is context-scoped. There is no unfiltered `GET /api/v1/signals`.
- Errors return `{ "error": { "code", "message", "details" } }` with a meaningful status.
- Mutating endpoints that touch the outside world return the created `proposed_action`, never the
  result of a send. Sending happens after review, through the executor.
- Timestamps in responses are RFC 3339 UTC with `Z`. The client formats them.

## 7. Frontend components

- The project is already initialised: style `base-nova`, **Base UI** primitives (`@base-ui/react`),
  base colour `neutral`, `rsc: true`, CSS variables on, Lucide icons, Tailwind v4 with
  `src/app/globals.css`. Do not re-run `init` — it rewrites `globals.css`.
- Magic UI is configured as a namespaced registry in `apps/web/components.json`:

  ```json
  "registries": { "@magicui": "https://magicui.design/r/{name}" }
  ```

  Install with `pnpm dlx shadcn@latest add @magicui/<component>` from `apps/web`.
- Because the base is Base UI rather than Radix, check a component's own docs before assuming a
  Radix API. Do not mix in `@radix-ui/*` packages.
- Reach for a primitive before a styled `div`: `Table`, `Sheet`, `Command`, `Tabs`, `AlertDialog`.
- Destructive and outbound confirmations use `AlertDialog`, never `Dialog`.
- Every list ships a designed empty, loading, and error state.
- See [ADR 0006](decisions/0006-frontend-stack.md) for where Magic UI applies and where it does not.

## 8. Git

- Branches: `phase-N/short-description`, `fix/short-description`, `docs/short-description`.
- Conventional commit subjects: `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `db:` for
  migrations. Imperative mood, under 72 characters.
- One logical change per commit. A migration, its sqlc regeneration, and the code that depends on it
  may share a commit; two unrelated migrations may not.
- Generated code (sqlc output, `lib/api/`) is committed, in the same commit as the source it was
  generated from.
- A commit changing a hard invariant, an ADR, or this file says so in the body and explains why.

## 9. Tests

- The router and the extractor have table-driven tests over real (anonymised) signal payloads in
  `db/seeds/`. These are the tests that matter; everything else is secondary.
- Ingestion has an idempotency test: ingest the same batch twice, assert row counts unchanged.
- Two standing guard tests: no path reaches the executor without a `proposed_action` row, and the
  `auto` autonomy level is unreachable before Phase 4.
- Store tests run against a real Postgres in Docker, not a mock. Domain tests need neither.
- Model calls are stubbed. No test spends tokens.

## 10. Configuration

- All configuration through environment variables, parsed once at startup into a typed struct. No
  `os.Getenv` scattered through the codebase, no `process.env` outside `next.config`.
- `infra/.env.example` lists every variable with a comment, updated in the same commit that
  introduces one.
- Secrets never enter the repository, a log line, or a prompt.
